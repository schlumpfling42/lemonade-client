# Coding Subgraph Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the agent run multi-step coding jobs through a `coding` subgraph — environment → investigate → plan → review → user plan approval → implement → verify — with the approved plan enforced by the graph and live progress in the window.

**Architecture:** A new annotated graph class `CodingGraph` (package `net.rka.ai.agent`, generated by `graph-processor` like `ApprovalGraph`) is added to `AgentGraph` as the `coding` subgraph node. The model starts it by calling the tool `startCodingJob(goal)`; the main router routes that call to `coding`. All job data lives in new `AgentGraph.State` keys; the plan-approval pause is a LangGraph4j interrupt before the inlined node `coding-planApproval`; `Agent.run` switches to `graph.stream(...)` to report progress.

**Tech Stack:** Java 27, LangChain4j 1.22, LangGraph4j 1.9.5, project annotations + `graph-processor`, Jackson, JavaFX 27, JUnit 6.

**Spec:** `docs/superpowers/specs/2026-10-18-coding-subgraph-design.md`

## Global Constraints

- Use LangGraph4j mechanisms (state keys, nodes, routers, subgraphs, interrupts, streaming); no side channels (CLAUDE.md, memory "use the graph").
- Plan approval covers **only** the plan's commands and file changes, **only inside the trusted folder**, and ends with the job.
- A tool call during implement that the plan doesn't cover never runs; the job goes back to `plan` → `review` → user approval.
- Plan commands match by **exact** whitespace-normalized text **and** working directory; **no wildcards**; a planned command may run any number of times.
- File entries: `create`/`modify` (file, or folder = path ending in `/` covering everything under it), `delete`, `move`; delete/move only on entries of that kind; a folder entry never allows deleting/moving the folder itself.
- The user's trusted commands (global + conversation) still run during a job without being in the plan.
- Investigate may run, without asking, only the fixed probe list (exact match) or the user's trusted commands.
- Verify: at most **3** attempts per job (re-plans don't reset); then report.
- Coding job commands use `CODING_COMMAND_TIMEOUT_SECONDS` (default **600**); probes use a short timeout (**20 s**).
- Environment cache: `environment.json` next to the global settings file (`~/chat/environment.json` by default), stale after **7 days**, refreshed when stale or when verify output shows a missing tool.
- SSH (`runRemoteCommand`) and memory tools (`remember`/`forget`) are **not offered** inside a coding job (my call: not covered by the spec's folder rule).
- Keep `docs/agent-graph.md`, the README diagram and the `AgentGraph` Javadoc in sync.
- This folder is **not a git repository**: tasks end with a passing build instead of a commit. Build/test command: `.\gradlew.bat build` (Windows) — expected `BUILD SUCCESSFUL`.

## Review Focus

1. A planned command called with a `workingDirectory` outside the folder (`..`, absolute path) — must be refused even though the command text matches (Task 1 test `commandOutsideFolderIsNotCovered`).
2. The model wraps the plan JSON in a Markdown code fence or adds prose around it — must still parse; truly invalid JSON gets one retry, then the job reports the failure (Task 1 `parsesFencedJson`, Task 3 `invalidPlanTwiceEndsJob`).
3. The model never finishes a step (keeps calling tools, or answers without doing anything) — a per-step limit of **15** model turns ends the job with a report instead of hanging (Task 4 `stepTurnLimitEndsJob`).
4. Verify fails because a tool isn't installed ("not recognized" / "command not found") — counts as a failed attempt and marks the environment cache stale (Task 5 `missingToolMarksEnvironmentStale`).
5. The user picks **Revise** several times — every revision must return to the plan approval pause, and Deny afterwards must leave the folder untouched (Task 6 `reviseThenDenyChangesNothing`).

### Task 2: Environment info with cache, and per-run command timeouts

**Files:**
- Create: `src/main/java/net/rka/ai/tools/EnvironmentInfo.java`
- Modify: `src/main/java/net/rka/ai/tools/CommandRunner.java` (timeout as a parameter), `src/main/java/net/rka/ai/tools/TerminalTools.java` (read the timeout invocation parameter), `src/main/java/net/rka/ai/agent/ToolCallRunner.java` (pass it)
- Test: `src/test/java/net/rka/ai/tools/EnvironmentInfoTest.java`, extend `src/test/java/net/rka/ai/tools/FileToolsTest.java` only if needed

**Interfaces:**
- Produces:
  - `public final class EnvironmentInfo` with `public static final List<String> PROBES` = exactly: `java -version`, `javac -version`, `gradle --version`, `mvn -v`, `node --version`, `npm --version`, `git --version`, `python --version`, `docker --version`.
  - `public EnvironmentInfo(Path cacheFile, Function<String, String> probeRunner, Clock clock)`; `public static EnvironmentInfo fromSettings()` (cache file = `Settings.globalFile().resolveSibling("environment.json")`, runner = `CommandRunner` with a 20 s timeout in the user's home folder, `Clock.systemUTC()`).
  - `public String summary()` — returns the cached summary if younger than 7 days, else runs every probe (a probe whose output says not recognized / not found / exit code ≠ 0 → `"<tool>: not installed"`), stores `{"checked": ISO-instant, "summary": text}` and returns it. The summary starts with the `systemInfo` lines (OS, shell, home, user).
  - `public void markStale()` — the next `summary()` re-probes.
  - `public static boolean isProbe(String command)` — exact (whitespace-normalized) member of `PROBES`.
  - `public static boolean looksLikeMissingTool(String output)` — true for "is not recognized", "command not found", "not found" in a command's stderr.
  - `TerminalTools.TIMEOUT_PARAMETER = "commandTimeoutSeconds"`; `runCommand` uses it when present (Integer seconds), else the global default.
  - `CommandRunner.run(List<String> commandLine, Path dir, Duration timeout)` (old 2-arg overload delegates with the default).
  - `ToolCallRunner.run(List<ToolExecutionRequest> calls, Path workFolder, FactBook facts, Integer timeoutSeconds)` — adds `TIMEOUT_PARAMETER` to the invocation parameters when not null; existing callers pass `null`.
